# Steno — scope and decisions

Status: draft for confirmation. Date: 2026-09-24.
Decisions below were settled in a structured interview. Nothing here is implemented yet.
Research background: `docs/research/2026-09-24-jamie-and-oss-landscape.md`.

## What Steno is

A bot-free meeting recorder for the Mac, for personal use by Nicolai and friends.
It captures system audio and microphone at the OS level, processes everything on the
Mac after the meeting, produces a summary, transcript and tasks, and pushes them
one-way into destinations via adapters. The app is the source of truth. Obsidian is
one adapter among others. Reading and downstream automation happen elsewhere, mainly
through agents that consume the exported files.

Reference product: Jamie (meetjamie.ai). Reference implementations: anarlog (MIT, Rust)
for capture and echo cancellation, Parrot (GPL, Swift) for two-lane capture, AudioCap
for Core Audio taps. Rebuilt from scratch, no forks.

## Non-goals for v1

- Windows, Linux, Intel Macs
- Bot-based capture of any kind
- Live transcript during the meeting
- Editing summary, transcript or task text inside the app
- Cross-meeting chat / Ask AI
- Custom user templates (fixed default set only)
- Google Drive, Nextcloud, ownCloud, WebDAV adapters (designed for, not built)
- Manual audio import UI
- Team, admin, hosted or paid features
- App Store distribution

## Capture (Mac)

- System audio via Core Audio process taps (`CATapDescription` -> process tap -> private
  aggregate device -> IOProc). Own process excluded.
- Microphone via AVAudioEngine as a separate lane.
- Two lanes kept separate: mic = "me", tap = "them". Deterministic speaker role for calls.
- Software acoustic echo cancellation on the mic lane using the tap as far-end reference.
  Apple VoiceProcessingIO is not used (it breaks system-audio capture). Candidates:
  SpeexDSP, WebRTC AEC3, or DTLN-aec ONNX ported to CoreML.
- In-person mode: single mic lane, full diarization.
- Phone calls: primary path is Continuity calls taken on the Mac and tapped there.
  First technical spike of the project: verify a Continuity call is tappable.
  Fallback: phone on speaker, Mac mic records the room. iOS cannot record calls.
- Recording start: popup prompt when another app opens the microphone, plus manual
  start/stop from the menu bar. Menu bar shows a visible recording indicator.
- Calendar via EventKit for titles and attendee names. No Google Calendar API.

## Processing (post-meeting, on the Mac)

1. Speech-to-text behind one engine protocol. Two implementations in v1:
   FluidAudio Parakeet TDT v3 and WhisperKit large-v3-turbo. Default chosen after a
   bake-off on real German/English/Denglish meetings. Transcript language auto-detected.
   Apple SpeechAnalyzer explicitly excluded.
2. Diarization via FluidAudio (pyannote community-1 offline pipeline) on the "them" lane,
   or the whole mix in in-person mode.
3. Speaker memory: WeSpeaker 256-dim embeddings persisted per person in SQLite, cosine
   match against known voices, running-average refinement. Unknown speakers get a
   ten-second sample clip for manual naming. LLM infers names from conversational context
   and calendar attendees as a prior. User can merge split speakers.
4. LLM post-processing over any OpenAI-compatible endpoint (base URL + API key only).
   Responsibilities: fix Denglish and anglicisms, casing and product names; produce summary
   from the selected template; extract tasks with assignee, priority, due date; infer
   speaker names. Output language follows the meeting language.
5. Templates: fixed default set modelled on Jamie (Default, Customer Discovery,
   Daily Standup, Interview). Selected after processing, summary can be re-run with
   another template. Custom templates later.

## Data model (canonical, what every adapter receives)

- Meeting: id, title, started, duration, language, source (mac-call, mac-in-person, phone),
  calendar event ref, tags
- Participants: person id, display name, role me/them, email if known
- Speakers: diarization cluster, matched person or unknown, embedding, sample clip
- Transcript: segments with start, end, speaker, text, lane
- Summary: markdown, template id, language
- Tasks: text, assignee, priority, due date, done
- Scratchpad: free text typed by the user
- Audio: path, retention rule
- Delivery: per-destination status and last error

## App UI (macOS)

- Menu bar item: start/stop, processing queue, launch at login (on by default).
- Main window: meeting list plus four tabs mirroring Jamie: Summary, Transcript, Tasks,
  Scratchpad. Display only.
- Editable: speaker assignment and naming, tags, template selection and re-run,
  per-meeting audio "keep" toggle, re-export trigger.
- Speaker review sheet after processing for unknown speakers (clip, name, pick from
  known people or calendar attendees).

## iOS companion

- Expo (React Native) dev-client app in `mobile/`, not Swift. Decided 2026-09-24 when
  adopting the house conventions: the phone runs no Steno processing, so sharing the
  Swift core buys nothing, while the Expo scaffold, EAS delivery lanes and design
  tokens from fifthset and june are proven and copied over as-is.
- Dumb recorder: record, stop, list with sync status. Nothing else.
- Local queue; recordings kept on the phone until delivered to the Mac.
- Transport: Bonjour discovery on the local network, one-time QR pairing, TLS with pinned
  keys, HTTPS upload to a listener in the Mac app. Local network only in v1.
- Processing happens on the Mac. Same pipeline as Mac in-person recordings.

## Adapters

One `Destination` protocol, one-way push, triggered on processing completion and on
explicit re-export. Designed so file-sync services and WebDAV can be added without
touching the core.

v1 adapter: **Obsidian vault folder** (path configurable).

Layout per meeting:
```
Meetings/
  2026-09-24-produktstrategie-90-10/
    2026-09-24-produktstrategie-90-10.md   # folder note: frontmatter, summary, scratchpad
    2026-09-24-produktstrategie-90-10 - Transcript.md
    2026-09-24-produktstrategie-90-10 - Tasks.md   # Obsidian Tasks plugin syntax
    transcript.vtt
    meeting.json
    audio.m4a                              # opt-in
```
- Slug: lowercase, umlauts transliterated, spaces to hyphens, max 60 chars.
- Frontmatter: date, duration, participants, tags, source, template, language.
- Tasks as `- [ ] text 📅 due ⏫ [[Assignee]]`. Erratum 2026-09-25: the Tasks
  plugin parses fields from the end of the line, so this order does not parse;
  the implemented line is `- [ ] text [[Assignee]] ⏫ 📅 YYYY-MM-DD` (see
  `2026-09-25-v1-program.md`, scope clarifications).
- Optional per-person pages linking their meetings.
- Re-export overwrites app-written files, never touches other files in the folder.
- The app never runs git.

Export formats produced: Markdown, VTT, JSON. SRT later.

## Retention and privacy

- Audio retention configurable: `0` deletes right after processing, empty never deletes,
  otherwise N days. Per-meeting keep toggle.
- Audio never leaves the Mac. Only transcript text goes to the LLM endpoint.
- Disk encryption relies on FileVault, no app-level encryption.

## Conventions adopted from fifthset, june, drio and mietprofi (2026-09-24)

- `AGENTS.md` with `CLAUDE.md` symlink; `.plans/` dated plans; `.agents/skills/`
  authoritative with `.claude/skills/` symlinks; Conventional Commits; REST-first `gh`.
- `.githooks/post-checkout` + `scripts/setup-worktree.sh` for worktree bootstrap.
- GitHub Actions: `repository-ci.yml` (actionlint, shell syntax), `swift-ci.yml`
  (path-gated, dormant until `Package.swift` exists), `mobile-ci.yml` and
  `mobile-cd.yml` (fingerprint-gated OTA vs TestFlight, ported from fifthset, iOS only).
- Mobile: pnpm 11, Biome, Expo SDK 57 dev client, uniwind + the house `global.css`
  tokens, `StartupGate`, `env.ts` contract, EAS fallback workflow.

## Open technical spikes (in order)

1. Continuity phone call audible in a process tap? Decides the phone-call story.
2. STT bake-off: Parakeet v3 vs WhisperKit turbo vs German Parakeet fine-tune on three
   real Denglish meetings, each followed by the LLM cleanup pass.
3. AEC choice: SpeexDSP vs DTLN-aec-on-CoreML, measured on a real call recording.
