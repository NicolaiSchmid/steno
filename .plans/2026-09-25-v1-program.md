## Repository layout for v1

```
Package.swift                one SwiftPM package, Swift 6, macOS 15+
Sources/StenoCore/           canonical model, protocols, GRDB store, pipeline, summary Markdown renderer, template data, settings, retention sweep, Testing/ (fakes, ManualClock, fixtures, snapshots)
Sources/StenoAudio/          capture (tap + mic lanes), echo cancellation, meeting detection, recording writer, AVFoundation decode and AAC mixdown, Testing/ (SyntheticCaptureBackend)
Sources/StenoSpeech/         FluidAudio + WhisperKit engines, FluidAudio diarizer, cosine speaker memory, model store, bake-off, Testing/ (FakeModelDownloader)
Sources/StenoLLM/            OpenAI-compatible client, structured output, cleanup and summary prompts, Testing/ (StubChatServer)
Sources/StenoAdapters/       renderers (Markdown, VTT, JSON), delivery coordinator, Obsidian folder destination
Sources/StenoHandover/       Mac side of the phone handover: Bonjour advertise, pairing, pinned TLS, swift-nio HTTP, chunked upload receiver
Sources/steno/               CLI: `record`, `process`, `export`, `deliver`; developer tools under `steno dev`
Tests/<Target>Tests/         one test target per module, plus stenoTests running the built CLI binary
Tests/StenoEndToEndTests/    the one real-pipeline test across modules; created by core, extended by every workstream's last step
Tests/Fixtures/              lowercase subfolders: audio, transcripts, templates, exports, speech, llm, meetings, handover, snapshots; MANIFEST.sha256
apps/macos/                  SwiftUI app, xcodegen project.yml, Sparkle, signing config
mobile/                      Expo iOS recorder (scaffold exists; the handover plan extends it)
```

Test support: fakes of StenoCore protocols live once, public, in `Sources/StenoCore/Testing/` with `ManualClock` (a `Clock<Duration>` for
every timer under test), `Fixtures.url(_:)` (`#filePath` to `Tests/Fixtures/`) and `Snapshot` golden compare (`STENO_UPDATE_SNAPSHOTS=1`
rewrites). Each module may add `Sources/<Module>/Testing/` for fakes of its own seams; no test target defines a fake another target needs.
`steno dev fixtures generate` is the one synthetic-audio generator: seeded SplitMix64 noise, integer phase accumulators, Int16 WAV,
byte-identical on every machine; `Tests/Fixtures/MANIFEST.sha256` pins the outputs and `FixtureManifestTests` regenerates and compares.
Fixtures use sequential UUIDs and fixed `Date(timeIntervalSince1970:)` values.

Module dependency direction, strictly one way: `StenoCore <- StenoAudio, StenoSpeech, StenoLLM, StenoAdapters, StenoHandover <- steno (CLI),
apps/macos`.

`StenoCore` depends on nothing but GRDB and Foundation. Every other module depends on `StenoCore` and on its own third-party packages only.
The app and the CLI wire concrete implementations together. CLI subcommands live in `Sources/steno/Commands/`, registered through the
core-owned root command.

Third-party packages, each entering `Package.swift` in the PR that uses it: GRDB.swift, swift-argument-parser (CLI only), FluidAudio (has a
binary xcframework target that the app archive signs and notarises), WhisperKit (repository `argmax-oss-swift`, product `WhisperKit`),
CSpeex (product `speex`, StenoAudio only), swift-certificates with swift-crypto and swift-asn1 (StenoHandover only),
swift-nio-transport-services plus swift-nio `NIOHTTP1` (StenoHandover only: the one port that accepts bytes from another device gets a
maintained HTTP/1.1 parser on Network.framework instead of a hand-written one), Sparkle (app target only). Anything else needs a sentence in
the plan.

Identifiers, immutable once a build ships: macOS bundle id `uno.schmid.steno.mac`, iOS bundle id `uno.schmid.steno`, team `KQB68F43PW`.

## Canonical model (owned by StenoCore)

Value types, `Codable`, `Sendable`, `Equatable`; `UUID` ids, `Date` timestamps, `TimeInterval` in-recording offsets. One JSON convention for
`meeting.json`, the handover wire and JSON columns: `StenoJSON.encoder()` / `decoder()` in StenoCore, camelCase keys (the Swift default),
sorted keys, ISO 8601 with fractional seconds, `Data` as standard base64.

- `Meeting`: id, title, startedAt, duration, language (`Locale.Language?`), source (`.macCall`, `.macInPerson`, `.phone`), calendarEventID,
  tags, state (`.recording`, `.queued`, `.processing`, `.ready`, `.failed(reason)`), templateID, summary (`SummaryDocument?`), scratchpad
  (user-typed free text), llmUsage (`LLMUsage?`), createdAt, updatedAt
- `SummaryDocument`: templateID, language?, sections `[SummarySection]` (id, heading, bullets `[SummaryBullet]` (lead, text)). Stored as
  JSON; Markdown is rendered by `SummaryMarkdown.render(_ export: MeetingExport)` at display and export time with the current speaker names,
  so renaming a speaker never re-runs the LLM.
- `Participant`: id, meetingID, personID?, displayName, role (`.me`, `.them`), email?. Calendar attendees are `Participant` rows with `role
  == .them` written by the app at recording start; there is no separate attendee list anywhere.
- `Person`: id, displayName, email?, embedding (`Embedding?`, 256 Float32, L2-normalised, BLOB, no CodingKey), sampleCount, createdAt
- `Speaker`: id, meetingID, clusterLabel ("Speaker 1", stable across re-exports), assignment (`SpeakerAssignment`: `.unknown`,
  `.suggested(personID, similarity)`, `.confirmed(personID)`; `personID` computed, nil for `.unknown`), embedding (no CodingKey),
  sampleClipRange (start, end), sampleClipURL (`URL?`, 10 s 16 kHz WAV written by the pipeline, deleted on confirm), clusterConfidence
  (diarizer cluster quality, not the match score)
- `TranscriptSegment`: id, meetingID, start, end, speakerID?, lane (`AudioLane`: `.mic`, `.system`, `.mixed`), text, rawText. `.mixed` means
  one room lane, fully diarized, no segment auto-assigned to the "me" participant; in-person, phone and the phone-on-speaker fallback all
  produce it.
- `MeetingTask`: id, meetingID, text, assigneePersonID?, assigneeName?, priority (`.low`, `.normal`, `.high`), dueDate?, done
- `Decision`: id, meetingID, text; `LLMUsage`: promptTokens, completionTokens, requests
- `AudioAsset`: id, meetingID, url (master), format (`AudioFormat`: `.caf48kFloat32`, `.m4aAAC`, `.wav16kInt16`), lanes, sidecars16k
  (`[AudioLane: URL]`), mixdownURL (AAC `.m4a` mono for the optional export, nil until the persist stage), retention
  (`.deleteAfterProcessing`, `.keepDays(Int)`, `.keepForever`), expiresAt? (stored: the sweep is one query and the keep toggle clears it)
- `Delivery`: id, meetingID, destinationID, status (`.pending`, `.delivered`, `.failed(String)`), lastAttemptAt, receipt
  (`DeliveryReceipt?`, JSON text column)
- `DeliveryReceipt`: root, folder (pinned at first delivery), files (relativePath, ownership `.owned` or `.managedBlock`, sha256),
  rendererVersion
- `PairedDevice`: id, name, pairedAt, lastSeenAt?
- `HandoverReceipt`: recordingID, deviceID, state (`.receiving`, `.verifying`, `.complete(meetingID)`, `.failed(String)`), byteCount,
  sha256, chunkSize, receivedChunks, createdAt, updatedAt
- `Settings` (one type, key/value table): audioFolder, defaultRetention (`.keepDays(30)`), inputDeviceUID, meetingDetectionEnabled,
  speechEngineID, speakerMatchThreshold (0.60; the margin 0.05 is a constant), modelsDirectory, llmBaseURL, llmModel, llmContextTokens (32
  000), defaultTemplateID ("default"), launchAtLogin, obsidian (`ObsidianSettings?`: vaultPath, peopleFolder?, includeAudio, taskTag?; nil
  means not configured). A second destination adds a second typed optional. API keys never live here; see `SecretStore`.
- `CalendarMatch.pick(events: [(id: String, start: Date, end: Date)], now: Date, lookahead: TimeInterval = 900) -> String?`: overlapping
  now, else the next within `lookahead`. Pure, in StenoCore, used by the app.

GRDB schema mirrors these one table per type, migrations append-only in `Sources/StenoCore/Storage/Migrations.swift`, FTS5 over segments and
over `meeting(title, summaryText)` where `summaryText` is the concatenated bullet text written beside the summary JSON. `MeetingStore`
offers two distinct merges: `mergePersons(keep:remove:)` (one person recorded twice, across meetings; re-points speakers and participants,
sample-count-weighted embedding mean computed in the store) and `mergeSpeakers(_:into:meetingID:)` (two clusters inside one meeting; moves
segments, averages embeddings, deletes the merged `Speaker`), plus `confirm(speakerID:person:memory:)`, the one operation that sets
`.confirmed`, enrols the embedding through `SpeakerMemory.enroll` and deletes the sample clip. Every write is `save`.

Templates: StenoCore owns `Resources/Templates/*.json` and `SummaryTemplate.bundled` (ids `default`, `customer-discovery`, `daily-standup`,
`interview`; per template `displayName`, `description`, `context`; per section `id`, `heading`, `instructions`, `required`). The
`instructions` and `context` strings are prompt text: the LLM workstream edits them in PRs against core; ids and headings are fixed by core.

## Protocols (owned by StenoCore, implemented elsewhere)

Signatures are the contract; plans add members only with a log entry here.

```swift
public protocol SpeechEngine: Sendable {         // ids "parakeet-v3", "whisperkit-large-v3-turbo"; actors declare id and supportedLanguages nonisolated let
    var id: String { get }; var supportedLanguages: Set<Locale.Language> { get }
    func prepare() async throws                  // download / load models
    func transcribe(_ audio: AudioBuffer16k, hint: Locale.Language?) async throws -> [RawSegment]
}
public protocol Diarizer: Sendable {             // clusters carry ranges, embedding, clusterConfidence, sampleClipRange
    func prepare() async throws; func diarize(_ audio: AudioBuffer16k) async throws -> DiarizationResult
}
public protocol EchoCanceller: Sendable {        // real-time safe: no allocation, no locks. farEnd is the far-end signal captured at the same instant as nearEnd; implementations own delay handling
    init(sampleRate: Double, frameSize: Int) throws
    func process(nearEnd: UnsafeBufferPointer<Float>, farEnd: UnsafeBufferPointer<Float>, out: UnsafeMutableBufferPointer<Float>)
}
public protocol LanguageModel: Sendable { func complete(_ request: LLMRequest) async throws -> LLMResponse }
public protocol Destination: Sendable {          // constructed with its typed settings; renders its own artefacts; previous == nil is the initial delivery
    var id: String { get }; func validate() async throws
    func deliver(_ meeting: MeetingExport, previous: DeliveryReceipt?) async throws -> DeliveryReceipt
}
public struct SpeakerMatch: Sendable, Equatable { public var person: Person; public var similarity: Float }
public protocol SpeakerMemory: Sendable {                                   // StenoSpeech, pure math over MeetingStore
    func candidates(for embedding: Embedding, limit: Int) async throws -> [SpeakerMatch]   // ranked by cosine; review sheet
    func enroll(_ embedding: Embedding, as person: Person) async throws               // running mean, capped sample count
}
extension SpeakerMemory {   // provided: best candidate at or above threshold and at least margin above the runner-up
    public func match(_ embedding: Embedding, threshold: Float, margin: Float = 0.05) async throws -> SpeakerMatch?
}
public protocol AudioDecoder: Sendable {         // StenoAudio (AVFoundation); core's WAVAudioDecoder reads 16 kHz mono WAV only
    func decode(_ asset: AudioAsset, lane: AudioLane) async throws -> AudioBuffer16k   // sidecar when present, else decodes CAF / m4a / WAV and resamples
    func mixdown(_ asset: AudioAsset, to url: URL) async throws                       // AAC m4a mono for the optional audio export
}
public protocol TranscriptCleaner: Sendable { func clean(_ input: CleanupInput) async throws -> CleanupOutput }       // StenoLLM, cleanup stage
public protocol MeetingSummarizer: Sendable { func summarize(_ input: SummaryInput) async throws -> SummaryOutput }  // StenoLLM, summarize stage
public protocol DeliveryDispatcher: Sendable { func deliverAll(meetingID: UUID) async -> [Delivery] }               // StenoAdapters; passes each destination's stored receipt as previous
public protocol SecretStore: Sendable {          // app: Keychain; CLI and tests: 0600 file or environment
    func secret(for key: SecretKey) async throws -> String?; func setSecret(_ value: String?, for key: SecretKey) async throws
}
public protocol HandoverIntake: Sendable { func admit(file: URL, metadata: RecordingMetadata, device: PairedDevice) async throws -> UUID }   // core RecordingIntake conforms; returns Meeting.id
```


`MeetingStore` is passed directly where a plan needs people or handover rows (one implementation, no protocol). Supporting types in
StenoCore: `AudioBuffer16k` (mono Float32, 16 kHz); `RawSegment` (start, end, text, language?, wordTimings?); `DiarizationResult { clusters:
[SpeakerCluster] }`, `SpeakerCluster` (label, ranges, embedding?, clusterConfidence, sampleClipRange?); `LLMRequest` (messages,
responseFormat `.text` / `.jsonObject` / `.jsonSchema(name:schema:strict:)`, temperature?, maxTokens?, purpose), `LLMResponse` (text,
finishReason `.stop` / `.length` / `.contentFilter` / `.other`, usage?, model?), `JSONValue`; `CleanupInput` (segments, language,
participants, speakers, knownPeople), `CleanupOutput` (segments, failedChunks, usage); `SummaryInput` (meeting, segments, speakers,
participants, knownPeople, template), `SummaryOutput` (title, summary `SummaryDocument`, decisions, tasks, speakerNames
`[SpeakerNameSuggestion]` (speakerID, name?, confidence, evidence), language?, usage); `MeetingExport` (schemaVersion = 1, meeting,
participants, speakers, persons, segments, tasks, decisions, audio?; its `StenoJSON` encoding is `meeting.json` everywhere);
`RecordingMetadata` (recordingID, startedAt, durationSeconds, byteCount, sha256, chunkSize, format `AudioFormat`, deviceName);
`SummaryTemplate`, `TemplateSection`; `SecretKey` (`.llmAPIKey`); `PipelineStage` (`String, CaseIterable`: decode, transcribe, diarize,
matchSpeakers, merge, cleanup, summarize, persist, deliver, retention); `PipelineFailure` (stage, reason); `MeetingEvent`
(`progress(meetingID, stage, fraction)`, `speakersNeedReview(meetingID, speakerIDs)`) on `MeetingEventBus`. Row changes (state, deliveries)
reach the app through `MeetingStore.observeMeetings()`, `observeMeeting(id:)` and `observeDeliveries(meetingID:)`; there is no second
channel for them.

## Pipeline (owned by StenoCore, `ProcessingPipeline`)

Input: a finished `AudioAsset` with one or two lanes. One actor with private typed functions, one per `PipelineStage`, each tested through
its inputs; `progress` is posted as each stage starts. Lanes are decoded one at a time inside the stage that needs them, so at most one
two-hour `AudioBuffer16k` (about 460 MB) is alive.

1. decode + transcribe: per lane, `decoder.decode(asset, lane:)` then `SpeechEngine.transcribe(_, hint:)`; the second lane's hint is the
   first lane's dominant language. Afterwards `meeting.language` = the `RawSegment.language` with the largest summed duration (nil when
   untagged).
2. diarize: the system lane (or the single `.mixed` lane), decoded again; clusters arrive with embedding, clusterConfidence and a
   diarizer-chosen sample clip range; the stage writes each cluster's 10 s clip as a 16 kHz WAV into `<meeting
   folder>/speakers/<speakerID>.wav` (`sampleClipURL`).
3. matchSpeakers: `SpeakerMemory.match(_, threshold: settings.speakerMatchThreshold)`; hit → `.suggested(personID, similarity)`, miss →
   `.unknown`.
4. merge + cleanup: one ordered transcript, `.mic` segments get the "me" participant, `.mixed` segments are never auto-assigned; then
   `TranscriptCleaner`, chunked, segment count and order preserved, `rawText` keeps the STT output.
5. summarize: `MeetingSummarizer` returns title, `SummaryDocument` for the selected template, decisions, tasks, speaker name suggestions, in
   the meeting language; validated JSON.
6. persist + deliver: for every asset that is not `.m4aAAC` call `AudioDecoder.mixdown` and set `mixdownURL` (`WAVAudioDecoder.mixdown`
   copies the file); mark `.ready`; post `speakersNeedReview` when any speaker is not `.confirmed`; then
   `DeliveryDispatcher.deliverAll(meetingID:)`.
7. retention: `.deleteAfterProcessing` sets `expiresAt = now`. `RetentionSweep` (StenoCore; the app runs it at launch and after each
   meeting) removes master, sidecars and mixdown together, never sample clips, updates the row, and continues past a missing file.

Failure: any thrown error becomes `PipelineFailure(stage:reason:)`; `process` catches it in one place, keeps what was persisted (the
transcript survives a cleanup or summarize failure) and sets `.failed(reason)`. `rerunSummary` runs summarize → deliver with another
template; `redeliver(meetingID:)` runs deliver alone and is the only re-export entry point. `enqueue(_ meeting:asset:)` writes
`Meeting(.queued)` plus the asset in one transaction and starts `process`; the app (Mac recordings) and `RecordingIntake` (phone) both call
it. Wall time enters through `now: @Sendable () -> Date`.

## Verification standard for every implementation agent

- Code compiles and tests pass on the GitHub-hosted `macos-15` job in `.github/workflows/swift-ci.yml` until the Forge runner is registered;
  an agent without local Swift pushes its branch and reads the run. The job runs `swift test --parallel --xunit-output .build/junit.xml`,
  writes totals plus every skipped test's name and message to `$GITHUB_STEP_SUMMARY`, fails when a skip message names none of the switches
  below, caches `.build` keyed on `Package.resolved` and the Swift version, and has `timeout-minutes: 60` (FluidAudio and WhisperKit compile
  cold in 15 to 25 minutes). Each PR reports the run URL.
- Every acceptance check in a plan is tagged `[ci]` (runs on the hosted job), `[opt-in: STENO_…]` (names its switch) or `[manual]` (a human
  on a Mac or phone; the PR says which were run).
- No real meeting audio in the repository; fixtures are generated (seeded, deterministic) or `say` output committed once with a `.ref.txt`,
  all under ten seconds. Tests never sleep on wall time: timers take an injected `Clock<Duration>` and tests drive `ManualClock`. Every test
  writing files uses a fresh temp directory; CLI tests run the binary with `HOME` set to a temp directory.
- No network in unit tests. Opt-in switches, all skipped (not failed) when unset: `STENO_AUDIO_TESTS=1` (real devices),
  `STENO_MODEL_TESTS=1` (downloads models), `STENO_LLM_TESTS=1` (one real endpoint via `STENO_LLM_BASE_URL`, `STENO_LLM_MODEL`,
  `STENO_LLM_API_KEY`), `STENO_KEYCHAIN_TESTS=1`. `STENO_UPDATE_SNAPSHOTS=1` rewrites goldens; a golden diff in a PR is a reviewed output
  change.
- `Tests/StenoEndToEndTests` runs the real pipeline across modules with no models and no network (loopback stub server only); core creates
  it with fakes everywhere, and each module workstream's last step replaces its own fake with the real type. The binary variant (`steno
  process` then `steno deliver`) lives in `stenoTests`. The app's UI smoke test runs hosted if XCUITest launches there (macOS spike S1);
  otherwise it is Forge-only and reported as skipped on hosted runs.

## Rules for every plan

- Start with a one-paragraph goal and an explicit non-goals list; list the public API as Swift signatures and every file to create with one
  line each.
- Steps of at most a day each, every acceptance check tagged `[ci]`, `[opt-in: STENO_…]` or `[manual]` and runnable by a reviewer.
- Name the tests (unit, integration, the one manual check only a human on a Mac can do) and the reviewer trap: the diff a reviewer rejects.
- Name the spikes that must succeed before the step that depends on them; say what the workstream needs from others, by protocol name.
- End with a "Deferred" list for anything cut beyond v1 scope. Under 400 lines. Decisions, not prose.

## Scope clarifications (2026-09-25, not scope changes)

- Scratchpad is free text typed by the user and therefore editable; Summary, Transcript and Tasks stay display-only ("display only" means
  generated text).
- The summary is stored as structured sections and rendered to Markdown when shown or exported; the scope's "Summary: markdown" describes
  the rendered form, which is what every adapter receives.
- The Obsidian Tasks line order in the scope was wrong (the plugin parses fields from the end): Steno writes `- [ ] text [[Assignee]] ⏫ 📅
  YYYY-MM-DD`. Erratum noted in the scope file.
- Frontmatter adds `title` (the file name is a slug); `duration` is whole minutes.
- The mic lane is a Core Audio IOProc sub-device of the tap aggregate; the scope's "AVAudioEngine" states the intent (separate lane), this
  fixes the mechanism.
- The speaker "sample clip" of the scope is a file (`Speaker.sampleClipURL`), not only a range, so the naming flow works under retention
  `0`.
