# Steno v1 program: workstreams, boundaries, verification

Status: orchestration document, written 2026-09-25 and reconciled the same
day against the seven workstream plans (log at the end). Scope authority
remains [`2026-09-24-initial-scope.md`](2026-09-24-initial-scope.md). This

## Repository layout for v1

```
Package.swift                      one SwiftPM package, Swift 6, macOS 15+
Sources/
  StenoCore/                       canonical model, protocols, GRDB store, pipeline, template data, settings, Testing/ (fakes, fixtures, snapshots)
  StenoAudio/                      capture (tap + mic lanes), echo cancellation, meeting detection, recording writer, AVFoundation decode and AAC mixdown
  StenoSpeech/                     FluidAudio + WhisperKit engines, FluidAudio diarizer, cosine speaker memory, model store, bake-off
  StenoLLM/                        OpenAI-compatible client, structured output, cleanup and summary prompts
  StenoAdapters/                   renderers (Markdown, VTT, JSON), delivery coordinator, Obsidian folder destination
  StenoHandover/                   Mac side of the phone handover: Bonjour advertise, pairing, pinned TLS, chunked upload receiver
  steno/                           CLI executable: headless pipeline runs, spikes, bake-offs, fixture generation
Tests/
  <Target>Tests/                   one test target per module, plus stenoTests running the built CLI binary
  Fixtures/                        lowercase subfolders: audio, transcripts, templates, exports, speech, llm, meetings, snapshots
apps/macos/                        SwiftUI app, xcodegen project.yml, Sparkle, signing config
mobile/                            Expo iOS recorder (scaffold exists; the handover plan extends it)
```

Test support lives once, public, in `Sources/StenoCore/Testing/`: fakes for
every protocol below, `Fixtures.url(_:)` (`#filePath` to `Tests/Fixtures/`),
`Snapshot` golden compare (`STENO_UPDATE_SNAPSHOTS=1` rewrites). No other
target defines fakes, fixture loaders or snapshot helpers. `steno fixtures
generate` is the one synthetic-audio generator; workstreams add cases to it.

Module dependency direction, strictly one way:
`StenoCore <- StenoAudio, StenoSpeech, StenoLLM, StenoAdapters, StenoHandover <- steno (CLI), apps/macos`.

`StenoCore` depends on nothing but GRDB and Foundation. Every other module
depends on `StenoCore` and on its own third-party packages only. The app and
the CLI wire concrete implementations together. CLI subcommands live in
`Sources/steno/Commands/`, registered through the core-owned root command.

Third-party packages, each entering `Package.swift` in the PR that uses it:
GRDB.swift, swift-argument-parser (CLI only), FluidAudio, WhisperKit
(`argmax-oss-swift`), CSpeex (StenoAudio only), swift-certificates with
swift-crypto and swift-asn1 (StenoHandover only), Sparkle (app target only).
Anything else needs a sentence in the plan.

Identifiers, immutable once a build ships: macOS bundle id
`uno.schmid.steno.mac`, iOS bundle id `uno.schmid.steno`, team `KQB68F43PW`.

## Canonical model (owned by StenoCore)

Value types, `Codable`, `Sendable`, `Equatable`; `UUID` ids, `Date`
timestamps, `TimeInterval` in-recording offsets.

- `Meeting`: id, title, startedAt, duration, language (`Locale.Language?`), source (`.macCall`, `.macInPerson`, `.phone`), calendarEventID, tags, state (`.recording`, `.queued`, `.processing`, `.ready`, `.failed(reason)`), templateID, summary (markdown), scratchpad (user-typed free text), llmUsage (`LLMUsage?`), createdAt, updatedAt
- `Participant`: id, meetingID, personID?, displayName, role (`.me`, `.them`), email?
- `Person`: id, displayName, email?, embedding (`Embedding?`, 256 Float32, L2-normalised, BLOB), sampleCount, createdAt
- `Speaker`: id, meetingID, clusterLabel ("Speaker 1", stable across re-exports), personID?, embedding, sampleClipRange (start, end), confidence
- `TranscriptSegment`: id, meetingID, start, end, speakerID?, lane (`AudioLane`: `.mic`, `.system`, `.mixed`), text, rawText
- `MeetingTask`: id, meetingID, text, assigneePersonID?, assigneeName?, priority (`.low`, `.normal`, `.high`), dueDate?, done
- `Decision`: id, meetingID, text; `LLMUsage`: promptTokens, completionTokens, requests
- `AudioAsset`: id, meetingID, url (master), format (`AudioFormat`: `.caf48kFloat32`, `.m4aAAC`, `.wav16kInt16`), lanes, sidecars16k (`[AudioLane: URL]`), mixdownURL (AAC `.m4a` mono for the optional export, nil until pipeline step 8), durationSeconds, retention (`.deleteAfterProcessing`, `.keepDays(Int)`, `.keepForever`), expiresAt?
- `Delivery`: id, meetingID, destinationID, status (`.pending`, `.delivered(Date)`, `.failed(String, Date)`), lastAttemptAt, receipt (`DeliveryReceipt?`, JSON text column)
- `DeliveryReceipt`: root, folder (pinned at first delivery), files (relativePath, ownership `.owned` or `.managedBlock`, sha256), rendererVersion
- `PairedDevice`: id, name, pairedAt, lastSeenAt?
- `HandoverReceipt`: recordingID, deviceID, meetingID?, state (`.receiving`, `.verifying`, `.complete(meetingID)`, `.failed(String)`), byteCount, sha256, chunkSize, receivedChunks, createdAt, updatedAt
- `Settings` (one type, key/value table): audioFolder, defaultRetention (`.keepDays(30)`), inputDeviceUID, meetingDetectionEnabled, speechEngineID, speakerMatchThreshold (0.60), modelsDirectory, llmBaseURL, llmModel, llmContextTokens (32 000), defaultTemplateID ("default"), launchAtLogin, destinations (`[String: DestinationSettings]`), enabledDestinationIDs. API keys never live here; see `SecretStore`.

`AudioLane.mixed` means one room lane, fully diarized, no segment
auto-assigned to the "me" participant; in-person, phone and the
phone-on-speaker fallback all produce it.

GRDB schema mirrors these one table per type, migrations append-only in
`Sources/StenoCore/Storage/Migrations.swift`, FTS5 over segments and
summaries from the first migration. `MeetingStore` conforms to `PersonStore`
and `HandoverStore` and offers two distinct merges: `mergePersons(keep:remove:)`
(one person recorded twice, across meetings; re-points speakers and
participants, sample-count-weighted embedding) and
`mergeSpeakers(_:into:meetingID:)` (two clusters inside one meeting; moves
segments, averages embeddings, deletes the merged `Speaker`).

Templates: StenoCore owns the data (`Resources/Templates/*.json`,
`TemplateRegistry.bundled`, ids `default`, `customer-discovery`, `daily-standup`,
`interview`; per template `displayName`, `description`, `context`; per section
`id`, `heading`, `instructions`, `required`). StenoLLM owns prompt wording only.

## Protocols (owned by StenoCore, implemented elsewhere)

Signatures are the contract; plans add members only with a log entry here.

```swift
public protocol SpeechEngine: Sendable {
    var id: String { get }                       // "parakeet-v3", "whisperkit-large-v3-turbo"
    var supportedLanguages: Set<Locale.Language> { get }
    func prepare() async throws                  // download / load models
    func transcribe(_ audio: AudioBuffer16k, hint: Locale.Language?) async throws -> [RawSegment]
}
public protocol Diarizer: Sendable {             // clusters carry ranges, embedding, confidence, sampleClipRange
    func prepare() async throws; func diarize(_ audio: AudioBuffer16k) async throws -> DiarizationResult
}
public protocol EchoCanceller: Sendable {        // real-time safe: no allocation, no locks. farEnd is the far-end signal
    init(sampleRate: Double, frameSize: Int) throws   // captured at the same instant as nearEnd; implementations own delay handling
    func process(nearEnd: UnsafeBufferPointer<Float>, farEnd: UnsafeBufferPointer<Float>, out: UnsafeMutableBufferPointer<Float>)
}
public protocol LanguageModel: Sendable { func complete(_ request: LLMRequest) async throws -> LLMResponse }
public protocol Destination: Sendable {
    var id: String { get }; var displayName: String { get }
    func validate(settings: DestinationSettings) async throws
    func deliver(_ export: MeetingExport, settings: DestinationSettings, mode: DeliveryMode) async throws -> DeliveryReceipt
}
public protocol SpeakerMemory: Sendable {                                   // StenoSpeech, pure math over PersonStore
    func match(_ embedding: [Float]) async throws -> (Person, Float)?        // best cosine match above threshold and margin
    func rankedCandidates(_ embedding: [Float], limit: Int) async throws -> [(Person, Float)]   // review sheet
    func enroll(_ embedding: [Float], as person: Person) async throws        // running mean, capped sample count
    func merge(_ source: Person, into target: Person) async throws -> Person // person merge, delegates to PersonStore
}
public protocol PersonStore: Sendable {                                     // MeetingStore conforms
    func persons() async throws -> [Person]; func save(_ person: Person) async throws; func mergePersons(keep: UUID, remove: UUID) async throws
}
public protocol AudioDecoding: Sendable {                                   // StenoAudio (AVFoundation); core fake reads 16 kHz mono WAV only
    func decode(_ asset: AudioAsset) async throws -> [AudioLane: AudioBuffer16k]   // sidecars16k when present, else decodes CAF / m4a / WAV and resamples
    func mixdown(_ asset: AudioAsset, to url: URL) async throws                    // AAC m4a mono for the optional audio export
}
public protocol TranscriptCleaner: Sendable {   // StenoLLM, step 6
    func clean(_ segments: [TranscriptSegment], context: CleanupContext) async throws -> CleanupResult
}
public protocol MeetingSummarizer: Sendable { func summarize(_ input: SummaryInput) async throws -> SummaryOutput }   // StenoLLM, step 7
public protocol DeliveryDispatcher: Sendable {  // StenoAdapters, step 9; fills reexport(previous:) per destination from stored receipts
    func deliverAll(meetingID: UUID, mode: DeliveryMode) async -> [Delivery]
}
public protocol SecretStore: Sendable {         // app: Keychain; CLI and tests: 0600 file or environment
    func secret(for key: SecretKey) async throws -> String?; func setSecret(_ value: String?, for key: SecretKey) async throws
}
public protocol HandoverStore: Sendable {       // MeetingStore conforms
    func pairedDevices() async throws -> [PairedDevice]; func insert(_ device: PairedDevice, tokenHash: Data) async throws
    func device(forTokenHash: Data) async throws -> PairedDevice?; func delete(deviceID: UUID) async throws
    func receipt(_ recordingID: UUID) async throws -> HandoverReceipt?; func upsert(_ receipt: HandoverReceipt) async throws
}
public protocol HandoverIntake: Sendable {      // StenoCore RecordingIntake conforms; returns Meeting.id
    func admit(file: URL, metadata: RecordingMetadata, device: PairedDevice) async throws -> UUID
}
```

Supporting types in StenoCore: `AudioBuffer16k` (mono Float32, 16 kHz);
`RawSegment` (start, end, text, language?, wordTimings?); `DiarizationResult
{ clusters: [SpeakerCluster] }`, `SpeakerCluster` (label, ranges, embedding?,
confidence, sampleClipRange?); `LLMRequest` (messages, responseFormat `.text`
/ `.jsonObject` / `.jsonSchema(name:schema:strict:)`, temperature?, maxTokens?,
purpose), `LLMResponse` (text, finishReason `.stop` / `.length` /
`.contentFilter` / `.other`, usage?, model?), `JSONValue`; `CleanupContext`
(language, participants, speakers, calendarAttendees, knownPeople),
`CleanupResult` (segments, failedChunks, usage); `SummaryInput` (meeting,
segments, speakers, participants, calendarAttendees, knownPeople, template),
`SummaryOutput` (title, summaryMarkdown, decisions, tasks, speakerNames
`[SpeakerNameSuggestion]` (speakerID, name?, confidence, evidence), language?,
usage); `MeetingExport` (meeting, participants, speakers, persons, segments,
tasks, decisions, audio?, `artifacts: [RenderedArtifact]` filled by
StenoAdapters), `RenderedArtifact` (kind `.folderNote` / `.transcript` /
`.tasks` / `.vtt` / `.json` / `.personPage` / `.audio`, fileName, data,
personID?), `DestinationSettings` (typed `JSONValue` dictionary),
`DeliveryMode` (`.initial`, `.reexport(previous: DeliveryReceipt?)`);
`RecordingMetadata` (recordingID, startedAt, durationSeconds, byteCount,
sha256, chunkSize, format, deviceName); `SummaryTemplate`, `TemplateSection`,
`SecretKey` (`.llmAPIKey`); `MeetingEvent` (`stateChanged`, `progress(meetingID,
stage, fraction)`, `meetingReady`, `speakersNeedReview`, `deliveryUpdated`) on
`MeetingEventBus`. There is no second pipeline event stream.

## Pipeline (owned by StenoCore, `ProcessingPipeline`)

Input: a finished `AudioAsset` with one or two lanes. Steps, each a separate
injectable type with its own tests; lanes are processed one at a time so at
most one two-hour `AudioBuffer16k` (about 460 MB) is alive:

1. Load 16 kHz mono per lane through `AudioDecoding` (sidecars when present).
2. Transcribe each lane with the configured `SpeechEngine`.
3. Diarize the system lane (or the single `.mixed` lane); clusters arrive
   with embedding, confidence and a diarizer-chosen sample clip range.
4. Match clusters against `SpeakerMemory` (threshold and margin from
   `Settings`); unmatched clusters become `Speaker` rows with `personID == nil`.
5. Merge lanes into one ordered transcript; `.mic` segments get the "me"
   participant, `.mixed` segments are never auto-assigned.
6. `TranscriptCleaner`: chunked, segment count and order preserved, `rawText`
   keeps the STT output.
7. `MeetingSummarizer`: title, summary from the selected template, decisions,
   tasks, speaker name suggestions, in the meeting language; validated JSON.
8. Persist; for Mac recordings call `AudioDecoding.mixdown` and set
   `AudioAsset.mixdownURL`; mark `.ready`; post `meetingReady` and, when
   applicable, `speakersNeedReview`.
9. `DeliveryDispatcher.deliverAll(meetingID:, mode: .initial)`.
10. Retention: `.deleteAfterProcessing` sets `expiresAt = now`; the app's
    sweep removes master, sidecars and mixdown together.

Failures in 6 or 7 keep the transcript and mark `.failed(reason)`; the user
re-runs. Another template runs 7 to 9 with `.reexport`; re-export runs 9.

## Verification standard for every implementation agent

- Code compiles and tests pass on the GitHub-hosted `macos-15` job in
  `.github/workflows/swift-ci.yml` until the Forge runner is registered; an
  agent without local Swift pushes its branch and reads the run. Each PR
  reports the CI run URL, the test count, and every skipped test with why.
- No real meeting audio in the repository; fixtures are generated (sine
  sweeps, `say` output) and under ten seconds.
- No network in unit tests. Opt-in switches, all skipped (not failed) when
  unset: `STENO_AUDIO_TESTS=1` (real devices), `STENO_MODEL_TESTS=1`
  (downloads models), `STENO_LLM_TESTS=1` (one real endpoint via
  `STENO_LLM_BASE_URL`, `STENO_LLM_MODEL`, `STENO_LLM_API_KEY`),
  `STENO_KEYCHAIN_TESTS=1`. `STENO_UPDATE_SNAPSHOTS=1` rewrites goldens; a
  golden diff in a PR is a reviewed output change.
- The app's UI smoke test runs hosted if XCUITest launches there (macOS spike
  S1); otherwise it is Forge-only and reported as skipped on hosted runs.

## Rules for every plan

- Start with a one-paragraph goal and an explicit non-goals list.
- List the public API the workstream exposes, as Swift signatures.
- List every file to create with one line each.
- Break work into steps of at most a day each, with an acceptance check per
  step that a reviewer can run.
- Name the tests: unit, integration, and the one manual check that only a
  human on a Mac can do.
- Name the spikes that must succeed before the step that depends on them.
- Say what the workstream needs from other workstreams, by protocol name.
- End with a "Deferred" list for anything cut from the plan beyond v1 scope.
- Keep it under 400 lines. Decisions, not prose.

## Scope clarifications (2026-09-25, not scope changes)

- Scratchpad is free text typed by the user and therefore editable; Summary,
  Transcript and Tasks stay display-only ("display only" means generated text).
- The Obsidian Tasks line order in the scope was wrong (the plugin parses
  fields from the end): Steno writes `- [ ] text [[Assignee]] ⏫ 📅 YYYY-MM-DD`.
  Erratum noted in the scope file.
- Frontmatter adds `title` (the file name is a slug); `duration` is whole minutes.
- The mic lane is a Core Audio IOProc sub-device of the tap aggregate; the
  scope's "AVAudioEngine" states the intent (separate lane), this fixes the mechanism.
