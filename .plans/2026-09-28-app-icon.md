# Steno: app icon

Status: proposal, 2026-09-28. Triggered by first-run feedback.

Binding plans: `.plans/2026-09-24-initial-scope.md` (two lanes, menu bar
indicator, audio never leaves the device), `.plans/2026-09-25-macos-app-and-release.md`
(asset catalog row in the file map, xcodegen and release pipeline),
`.plans/2026-09-25-v1-program.md` and `.plans/2026-09-27-ios-bundle-id.md`
(immutable identifiers, iOS delivery). Mobile delivery constraints:
`mobile/README.md` ("Anything that moves the fingerprint").

## Goal

Give Steno one icon that is recognisably its own in the Dock, in Launchpad,
in the Finder and on an iPhone home screen, that says "two lanes of a
conversation, written down on this machine", and that is produced from one
committed vector source by one script, so nobody ever hand-exports PNGs
again. Nothing in the running app changes besides the icon the system shows.

## Concepts

All three share the frame: the macOS grid (1024 canvas, 824 rounded square,
radius 185), a near-black plate that reads as the app's dark canvas, a white
glyph, one semantic accent, no text, no purple.

### 1. Two-lane waveform

Metaphor: one conversation, two lanes. Shape: five rounded vertical bars in
the SF Symbols `waveform` rhythm, cut along the horizontal centre line into
an upper lane ("them") and a lower lane ("me") with different heights per
lane, the lower centre bar in live green. Palette: plate `#303034` to
`#141416`, bars `#FFFFFF`, accent `#62B06F`. At 512 px the split reads as two
voices; at 32 px it is still a waveform with a gap; at 16 px it is a grey
smudge on a dark plate. Differs from Jamie (no letter, no purple) but sits in
the crowd of Voice Memos, Otter and every recorder that uses a waveform, and
the menu bar already shows a waveform, so the Dock would show the same idea
twice. Rendered and rejected for the 16 px read.

### 2. Shorthand stroke

Metaphor: the stenographer's hand. Shape: a single continuous Gregg-style
stroke, a loop that opens into a long horizontal tail, drawn as one thick
round-capped path, with a green dot where the pen lifts. Palette as above.
At 512 px it is elegant and unmistakably about writing; at 32 px it becomes
an ambiguous squiggle; at 16 px it is a comma. Nobody in the set owns a
calligraphic mark, so it is distinct, but it says "note taking" more than
"recording" and it needs a bezier that renders identically in librsvg and
CoreSVG, which the plate and pills do not. Not rendered; kept as the
fallback if the owner wants a warmer, hand-made feel.

### 3. Steno pad

Metaphor: the Gregg-ruled steno pad, the one object that is literally
stenography: a page with a vertical rule down the middle that splits it into
two columns. Steno's product is exactly that page: the "them" lane written on
the left, the "me" lane on the right, and the newest line, the one being
written right now on this Mac, highlighted in live green. Shape: one
vertical grey rule, three left-aligned and three right-aligned rounded lines
of varying length, nothing else. Palette: plate `#303034` to `#141416`,
rule `#A3A3A3`, lines `#FFFFFF`, live line `#62B06F`. At 512 px it is a calm,
symmetrical page; at 32 px both columns, the rule and the green line are
intact; at 16 px it still reads as "two columns with a green mark", which is
a silhouette no other app in the set has. Differs from Jamie in every axis:
dark instead of purple, an object instead of a letter, green instead of
white as the only colour. Rendered at 512, 32 and 16 and kept.

## Decision

Concept 3, the steno pad, with the live line at the bottom right.

Reasons:

1. It is the only one of the three that survives 16 px as a distinct shape,
   and 16 and 32 px are what the Finder sidebar, Spotlight and the Dock at
   minimum size actually show.
2. It is the only concept that is not a waveform, a letter or a red dot, so
   it is distinct from Jamie and from the whole recorder category at a glance.
3. The name is the metaphor. A steno pad's centre rule is exactly the "two
   lanes kept separate" decision in the scope, and the highlighted newest line
   is "written here, now", which is the on-device promise without a padlock.
4. It is built from rectangles with rounded corners and one linear gradient.
   librsvg (Linux, Homebrew) and CoreSVG (Xcode, Preview) render these
   identically, so the committed PNGs do not depend on which machine produced
   them.
5. The accent is the existing `live-bright` token, not a new brand colour, and
   it stays out of the red the menu bar uses for "recording now", so the Dock
   icon never looks like a stuck recording indicator.

Green sits at the bottom right rather than top right (rendered both): a pad
is written top down, so the bottom line is the current one, and the heavier
bottom row grounds the composition. At 16 px the difference is negligible.

## Design spec

Grid (Apple macOS icon grid, in 1024 pt canvas units):

- Canvas 1024 x 1024, transparent. The system adds the drop shadow; the SVG
  draws none.
- Plate: 824 x 824 at (100, 100), corner radius 185 (22.4 per cent of the
  side, the Big Sur curve to within a pixel at every shipped size). Fill:
  vertical linear gradient `#303034` (top) to `#141416` (bottom). Hairline:
  a 3 pt stroke of white at 10 per cent opacity inset by 2 pt (the house
  `border` token, 10.2 per cent white), radius 183.
- Glyph bounding box: x 232 to 792 (560 wide, 68 per cent of the plate),
  y 292 to 732 (440 tall, 53 per cent). Centred horizontally and vertically
  on the plate.
- Rule: 24 x 440 at (500, 292), radius 12, fill `#A3A3A3` (house
  `muted-foreground`, dark). Solid grey rather than translucent white so
  every renderer produces the same pixel.
- Lines: height 68, radius 34 (full pills). Row centres y = 352, 512, 672
  (pitch 160). Left column right-aligned to x = 444, right column
  left-aligned to x = 580, leaving a 56 pt gutter either side of the rule.
  - Left ("them"): widths 212, 148, 188, so x = 232, 296, 256.
  - Right ("me"): widths 168, 128, 212, all at x = 580.
- Colours: lines `#FFFFFF`; the bottom right line `#62B06F` (house
  `live-bright`, dark). Palette in full: `#303034`, `#141416`, `#FFFFFF`,
  `#A3A3A3`, `#62B06F`, plus white at 10 per cent for the hairline.
- Minimum feature at 16 px: the rule is 0.4 px and the lines 1.1 px tall
  after scaling; librsvg's anti-aliasing keeps both visible, checked in the
  16 px render.

iOS variant (see step 6): the same SVG with the viewBox set to the plate
(`100 100 824 824`) and both plate radii set to 0, so the plate fills the
whole 1024 square and iOS applies its own mask. Flattened to RGB without an
alpha channel.

Menu bar: unchanged, SF Symbols `waveform` and `record.circle.fill` stay.
Reasons: the symbols follow the menu bar's point size, weight and vibrancy
for free; the multicolor recording symbol is the system's own "recording"
vocabulary; and the pad glyph at 18 pt would need custom template PNGs at
1x and 2x plus a second recording variant, for a mark the user sees as a
tiny outline next to the clock, where the waveform is at least as legible.
The icon and the symbols share the rounded-bar vocabulary, which is enough
harmony. If a template glyph is wanted later, it is the `#glyph` group of
the SVG rendered white on transparent at 18 and 36 px with `rule` and
`live` set to white, saved as `MenuBarIdle.imageset` with
`"template-rendering-intent": "template"`.

## SVG source

Committed as `apps/macos/Steno/Resources/AppIcon.svg` (identical to this
block; the file is the source of truth, this block is for review).

```svg
<?xml version="1.0" encoding="UTF-8"?>
<!-- Steno app icon. Source of truth for every raster icon asset; regenerate
     them with apps/macos/scripts/make-app-icon.sh. Design notes and geometry:
     .plans/2026-09-28-app-icon.md. -->
<svg xmlns="http://www.w3.org/2000/svg" width="1024" height="1024" viewBox="0 0 1024 1024">
  <defs>
    <linearGradient id="plate-gradient" x1="0" y1="0" x2="0" y2="1">
      <stop offset="0" stop-color="#303034"/>
      <stop offset="1" stop-color="#141416"/>
    </linearGradient>
  </defs>
  <!-- Plate: the macOS icon grid's 824 pt rounded square centred on the
       1024 pt canvas. The system draws the drop shadow. -->
  <g id="plate">
    <rect id="plate-fill" x="100" y="100" width="824" height="824" rx="185" fill="url(#plate-gradient)"/>
    <rect id="plate-hairline" x="102" y="102" width="820" height="820" rx="183" fill="none" stroke="#ffffff" stroke-opacity="0.1" stroke-width="3"/>
  </g>
  <!-- Glyph: a steno pad. The centre rule splits the page into two columns,
       "them" on the left and "me" on the right; the newest line, the one
       being written right now on this Mac, is live green. -->
  <g id="glyph">
    <rect id="rule" x="500" y="292" width="24" height="440" rx="12" fill="#a3a3a3"/>
    <rect x="232" y="318" width="212" height="68" rx="34" fill="#ffffff"/>
    <rect x="296" y="478" width="148" height="68" rx="34" fill="#ffffff"/>
    <rect x="256" y="638" width="188" height="68" rx="34" fill="#ffffff"/>
    <rect x="580" y="318" width="168" height="68" rx="34" fill="#ffffff"/>
    <rect x="580" y="478" width="128" height="68" rx="34" fill="#ffffff"/>
    <rect id="live" x="580" y="638" width="212" height="68" rx="34" fill="#62b06f"/>
  </g>
</svg>
```

## Implementation steps

1. Commit the source. `apps/macos/Steno/Resources/AppIcon.svg` as above.
   It lives beside `Assets.xcassets`, not inside it, so the asset compiler
   never sees it; xcodegen adds it to the target's resources as a plain file,
   which is harmless (2 KB) and lets the About window or an onboarding page
   load the vector later.

2. Write `apps/macos/scripts/make-app-icon.sh` (bash 3.2 compatible,
   `set -euo pipefail`, executable, syntax-checked by repository CI like the
   other scripts). Behaviour, exactly:
   - Paths relative to the script: `SVG=../Steno/Resources/AppIcon.svg`,
     `SET=../Steno/Resources/Assets.xcassets/AppIcon.appiconset`,
     `IOS=../../../mobile/assets/icon.png`.
   - Renderer: ImageMagick 7 `magick` with the librsvg delegate, the one tool
     that renders, resizes, strips alpha and verifies on both platforms. The
     script checks `command -v magick` and `magick -list format | grep -q
     '^ *RSVG'`, and exits 1 with `brew install imagemagick` (the formula
     depends on `librsvg`) or `nix-shell -p imagemagick librsvg` as the hint.
     ImageMagick's internal `MSVG` renderer is refused because its gradient
     and anti-aliasing output differs, and `qlmanage -t` and `sips` are not
     used because neither takes a target pixel size for SVG input and both
     colour-manage the output.
   - Mac renders: for each pixel size `px` in 16 32 64 128 256 512 1024 run
     `magick -background none -density $((96 * px / 1024)) "$SVG" -strip
     -define png:exclude-chunks=date,time PNG32:"$tmp/$px.png"`. Density
     drives librsvg's vector rasterisation at the exact size, so no bitmap
     resampling happens. Copy each render to the appiconset filenames:

     | Size | Scale | Pixels | Filename |
     |---|---|---|---|
     | 16x16 | 1x | 16 | `icon_16x16.png` |
     | 16x16 | 2x | 32 | `icon_16x16@2x.png` |
     | 32x32 | 1x | 32 | `icon_32x32.png` |
     | 32x32 | 2x | 64 | `icon_32x32@2x.png` |
     | 128x128 | 1x | 128 | `icon_128x128.png` |
     | 128x128 | 2x | 256 | `icon_128x128@2x.png` |
     | 256x256 | 1x | 256 | `icon_256x256.png` |
     | 256x256 | 2x | 512 | `icon_256x256@2x.png` |
     | 512x512 | 1x | 512 | `icon_512x512.png` |
     | 512x512 | 2x | 1024 | `icon_512x512@2x.png` |

     The 32, 256 and 512 px renders are each written twice under two names,
     which is what Xcode expects; there are no symlinks in an asset catalog.
   - Rewrite `Contents.json` in full from a heredoc with the ten entries in
     the order above, each with `filename`, `idiom: mac`, `scale`, `size`,
     and the `info` block unchanged. Writing the whole file rather than
     patching it is what makes the step idempotent.
   - iOS render: `sed -e 's/viewBox="0 0 1024 1024"/viewBox="100 100 824
     824"/' -e 's/rx="185"/rx="0"/' -e 's/rx="183"/rx="0"/' "$SVG" >
     "$tmp/ios.svg"`, then `magick -background '#141416' -density 96
     "$tmp/ios.svg" -alpha remove -alpha off -strip -define
     png:exclude-chunks=date,time PNG24:"$IOS"` (creates `mobile/assets/`).
     Then `magick identify -format '%[opaque]' "$IOS"` must print `True`;
     otherwise exit 1. App Store Connect rejects a 1024 icon with an alpha
     channel, and Expo's own flattening should not be relied on.
   - `--check`: render everything into `$tmp` and `cmp` against the committed
     files, exit 1 on any difference and list the paths. `-strip` and the
     excluded `date,time` chunks make the PNG bytes deterministic for a given
     ImageMagick and librsvg version, so `cmp` is enough. Without `--check`
     the script overwrites in place and prints one line per file.
   - The script never runs in CI. The PNGs are committed; CI builds them into
     `Assets.car` like any other resource. This keeps Forge and `macos-15`
     free of a new Homebrew dependency, which is the rule
     `install-xcodegen.sh` already follows.

3. Run the script once, commit the ten PNGs, the rewritten `Contents.json`
   and `mobile/assets/icon.png` together with the script and the SVG in one
   commit: `feat(macos): add the steno pad app icon`.

4. Tests, in `apps/macos/StenoTests/AppIconTests.swift` (new file, same
   hostless style as `InfoPlistTests`):
   - `testAppIconSetListsEveryFileAndEveryFileExists`: decode
     `TestSupport.appRoot/Steno/Resources/Assets.xcassets/AppIcon.appiconset/Contents.json`
     with `JSONSerialization`; assert exactly ten `images`, every entry has
     a non-empty `filename`, the file exists, and its `NSBitmapImageRep`
     `pixelsWide` and `pixelsHigh` equal `size * scale`. This is the trap
     that the current repository falls into: a valid `Contents.json` with no
     files compiles silently.
   - `testBuiltAppCarriesTheIcon`: from `InfoPlistTests.appInfo()` assert
     `CFBundleIconName == "AppIcon"` and that
     `Steno.app/Contents/Resources/AppIcon.icns` exists and is larger than
     100 KB (ten sizes of a real image; the empty set produces a few
     hundred bytes).
   - `testIconSourceIsCommittedBesideTheSet`: `AppIcon.svg` exists and its
     text contains `id="glyph"` and `id="live"`, so the script's `sed` and a
     future template export keep working.
   - Extend `ReleaseScriptsTests` with one case: running
     `make-app-icon.sh` with `PATH=/usr/bin:/bin` (no `magick`) exits 1 and
     mentions `brew install imagemagick`, so the missing-dependency path is
     the friendly one.

5. `apps/macos/project.yml`: no change. `ASSETCATALOG_COMPILER_APPICON_NAME`
   already names the set and the resources folder is already in `sources`.
   Confirm with `xcodegen generate` that `AppIcon.svg` is listed under
   Resources, not compiled.

6. Mobile, `mobile/app.config.ts`: add `icon: "./assets/icon.png"` at the top
   level and `ios.icon: { light: "./assets/icon.png", dark:
   "./assets/icon.png" }` (the dark plate is its own dark variant; no tinted
   variant in v1, see open questions). Remove step 2 from the pre-first-build
   list in `mobile/README.md:128` and note the icon source path in the README
   file map. Fingerprint: adding the icon changes the Expo native fingerprint
   and forces a TestFlight build on the next `mobile/**` merge to `main`.
   That is intended, and it is free if it lands before the first TestFlight
   build, which the README already asks for; if a build has shipped by then,
   it costs one native build, not a new identifier. Bundle ids, slug and EAS
   ids do not change.

7. Documentation: one paragraph in `apps/macos/README.md` (or the top-level
   README's macOS section, whichever the docs-writing skill points to)
   saying that `AppIcon.svg` is the source, `make-app-icon.sh` regenerates,
   and `make-app-icon.sh --check` is how a reviewer proves the PNGs match.

## Verification

- `bash -n apps/macos/scripts/make-app-icon.sh` (repository CI does this).
- On a machine with ImageMagick and librsvg: `apps/macos/scripts/make-app-icon.sh
  && git status --porcelain` shows only the intended files, and running it a
  second time followed by `--check` exits 0 with no diff (idempotent).
- `magick identify` on `icon_16x16.png` through `icon_512x512@2x.png` reports
  the ten expected pixel sizes and `srgba`; on `mobile/assets/icon.png`
  reports `1024x1024 srgb` and `opaque=True`.
- `xcodegen generate --spec apps/macos/project.yml && xcodebuild -scheme
  Steno build` then `open` the built app: the Dock, the Finder Get Info
  pane and the About window show the steno pad; `⌘-Tab` at the default Dock
  size shows the two columns and the green line. Check both light and dark
  menu bar and Dock: the plate is the same dark grey against both.
- `swift-ci.yml` app job: `AppIconTests` pass; the previously silent empty
  set now fails `testAppIconSetListsEveryFileAndEveryFileExists` if anyone
  deletes a PNG.
- Mobile: `pnpm check` in `mobile/`; `npx expo config --type prebuild | grep
  icon` shows the path; the mobile CD fingerprint comment on the PR reports a
  changed native fingerprint, as expected.
- Visual previews from this proposal (rendered on Linux with the librsvg
  delegate): `/tmp/steno-icon-1024.png`, `/tmp/steno-icon-512.png`,
  `/tmp/steno-icon-32.png`, `/tmp/steno-icon-16.png`,
  `/tmp/steno-icon-ios-1024.png`. They are previews, not the committed
  assets; the script produces those.

## Open questions

1. Should the About window and the onboarding welcome page reuse the SVG
   (`NSImage(contentsOf:)` renders SVG since macOS 11) instead of loading
   the 512 PNG from the asset catalog? Free if yes; out of scope here.
2. iOS 18 tinted icons need a greyscale glyph on transparent. The `#glyph`
   group rendered white on transparent would do, but the home screen tint
   pass flattens the green, so the mark loses its accent. Ship without a
   tinted variant in v1 and revisit when the phone app gets a home screen
   pass.
3. Plate darkness: `#303034` to `#141416` matches the app's dark canvas and
   stays visible on a dark Dock because the Dock is translucent grey, not
   black. If the owner prefers a light icon (off-white `#FAFAFA` plate,
   `#0A0A0A` glyph, same green), only the two gradient stops and three fill
   values change; everything else in this plan holds.
4. Whether to add a Linux CI job that runs `make-app-icon.sh --check`. It
   would need the exact ImageMagick and librsvg versions pinned (Ubuntu's
   `imagemagick` package may use a different SVG delegate), so the check is
   left to the developer who regenerates and to `AppIconTests`, which
   guards presence and pixel size rather than bytes.
5. The reserved "menu bar template icons (idle, recording)" row in
   `.plans/2026-09-25-macos-app-and-release.md:136` stays unfulfilled by
   this decision (SF Symbols remain). Amend that plan's file map or accept
   the row as optional when this plan is approved.
